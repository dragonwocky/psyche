# Changelog

## v1.0.0 (unreleased)

A headless rewrite, from the search built into
[template-cms](https://github.com/dragonwocky/template-cms): psyche keeps the
search's state and matching, and sites render their own panel.

### Added

- `createSearch`, a store without a framework: its state (`getState`,
  `subscribe`), actions (`open`, `input`, `select`, `visit`...), and `connect()`
  for its keyboard shortcuts and page handling.
- `psyche/solid`: `useSearch`, the store's state as a Solid signal.
- Matching in a web worker (`createSearchWorker`), which fetches the index
  only once search is needed, or on the page with `worker: false`.
- `limit`, `excerpt`, `lead` and `threshold` options for the number of results,
  their excerpts and how loosely queries match, which were fixed.
- Fuzzy matching of fields of any name and tier (`psyche/match`), passed to
  `createSearch`, with an excerpt around each match. A field's value is text,
  or a record matched by the same fields, either linked (`{ value, href }`), or
  an array of them. `match` finds every match in a value, values, a record or
  records, with their scores, and `rank` orders them. A text's match is
  `{ value, match?, href?, score }`, and a record's is
  `{ value, match?, matches, href?, score }`.
- Highlighting with the CSS Custom Highlight API (`psyche/highlight`), in the
  elements a site hands to the store's `refs`, and on the page a result links
  to (`?search=`), which the store's `page` state has for the site's components.
  Sites highlight in their own components by `rangesOf(target, match)`, for a
  match from any of `psyche/match`'s functions, and `highlight(ranges)`.
- Results are their index entries' matches, as `match` returns them for a
  record, linked to their best match's value (e.g. a heading's `#id`) by the
  store's `href(link, result, query)`. They can be grouped by a record's key,
  and an empty query lists a sitemap.
- Examples for Astro (a Solid panel) and Lume 4 (a panel in plain DOM).

### Changed

- Every matching value keeps its match, not only a record's best, and queries
  match more tightly by default (`threshold` 0.4, from 0.3).
- Installs with pnpm and node (from git tags), not Deno. Solid is an optional
  peer dependency, only for `psyche/solid`.
- The index is generated by the site, as records linked to their pages
  (`{ href, value: record }`), whose other values are passed through to
  results as `data`.

### Removed

- The search panel, its styles and icons: sites render their own.
- The Deno client, `psyche.min.mjs` and `psyche({...}).register()`.
- The Lume indexer (`indexers/lume.ts`).
- FuzzySet and feather-icons, and the hotkey registry (`registerHotkey`).
- The `theme` and `messages` options, and the built-in ⌘/CTRL + K shortcut:
  sites open the search by their own, e.g. with `psyche/keys`' `isShortcut`.

## v0.3.4 (2022-02-23)

## Fixed

- Replaced `requestIdleCallback` with `setTimeout` for Safari support.

## v0.3.3 (2022-01-30)

## Added

- `scroll-behaviour: smooth`

## v0.3.2 (2022-01-29)

### Changed

- Focused results are outlined to differentiate them from
  hovered results.

### Fixed

- `<mark></mark>` elements are styled according to the accent
  colour (the browser's built-in yellow highlight doesn't contrast
  well with other light colours).

## v0.3.1 (2022-01-28)

### Added

- Exported the `platformModifier` string for direct use
  (e.g. in search trigger labels).

### Removed

- Removed `{{platformModifier}}` tag replacement.

### Fixed

- Depend on the more reliable `site.url(<string> page.data.url)`
  for detecting Lume page URLs.

## v0.3.0 (2022-01-27)

### Added

- Adjusted and exposed the internal hotkey registration
  for use with a `platformModifier` property equivalent
  to the `{{platformModifier}}` tag.

### Changed

- Moved the Lume indexer's slugifer to the `indexers/shared.ts` file.
- Renamed the `{{modifier}}` tag to `{{platformModifier}}`.

### Fixed

- Slugifier no longer slices the last letter off
  slugs generated from headings without spaces.
- Modals close when results are clicked.
- Removed `console.log` debug statement.
- Gave `position:sticky` priority over `position:-webkit-sticky`.

## v0.2.0 (2022-01-26)

### Added

- Configuration options.
- Zoom-in-zoom-out modal open animation.
- Rounded scrollbar style.
- Footer copyright.
- `{{modifier}}` tag for platform-specific hotkeys
  (replaced with `⌘` on MacOS and `CTRL` on other platforms).
- Added `list` and `code` result types.

### Changed

- Component constructed on the client-side instead of during site generation.
- Scoped CSS styling instead of utility classes.
- More efficient search caching logic.
- Tweaked text sizing and positioning.

### Fixed

- Slugs generated by the Lume indexer no longer cut words in half.
- The Lume indexer uses Deno's import map to infer the current version of
  Lume and prevent dependeny conflicts on Lume updates.
- Empty `<mark></mark>` elements are no longer added to results.
  This occured when the search input was empty and only `{ type: "page" }`
  results were displayed, and would cause e.g. `&` to be displayed as `&amp;`.

## v0.1.0 (2021-12-31)

First version, hardcoded into the notion-enhancer website.

- Site indexing performed during the build process.
- Basic exact & fuzzy search logic.
- Interface contained within a toggleable modal and styled with utility classes.
- A desktop-only footer with a list of available navigation hotkeys.
